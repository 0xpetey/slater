# A log file and crash reports, kept on this Mac

Slater crashed six times between 2026-09-28 and 2026-10-03 and left little to work from: the unified log had rolled past the moment, and macOS's `.ips` reports sit in a folder nobody looks in, without what the app was doing beforehand. So Slater now writes its own log, `~/Library/Logs/Slater/Slater.log`, which is the one thing it writes to disk unasked (ADR 0001 otherwise stands). Each line goes straight to the file, unbuffered, so the lines before a crash survive it; the file rotates at about 1 MB, keeping one older file. It holds what the unified log already held: timings, counts and error messages, never recognized text or translations. Signal handlers (SIGTRAP, SIGABRT, SIGSEGV, SIGBUS, SIGILL, SIGFPE) and an uncaught-exception handler add the crashing thread's backtrace to the log, then hand the crash back to macOS, so its own report is still written with the real stack.

A marker file exists while Slater runs. One found at launch means the last session didn't quit cleanly (a crash, a force quit, a power loss; `kill` and Quit remove it), and Slater then writes a report to `~/Library/Logs/Slater/Reports/` and says so in an alert. Report a Problem… in the menu writes the same report on demand. A report is one text file: the steps for posting it as a GitHub issue, the app and macOS versions, the last 600 log lines, and macOS's crash report for the session. Ten are kept.

Nothing is uploaded. A crash reporting service was not considered: the report leaves the Mac only when the user attaches it to an issue themselves, after reading it, which is what ADR 0001 requires of anything that leaves the Mac.
